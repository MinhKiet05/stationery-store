## User API

Authenticated users: GET/PUT `/api/users/me`, PUT `/api/users/me/password`.
Admins: GET `/api/users`, GET `/api/users/{id}`, PATCH `/api/users/{id}/status`.

Profile input: email (required), fullName, phoneNumber, address. PUT clears omitted optional fields. Role/status/username cannot be edited through this request. Password input: oldPassword and newPassword (8-72 characters, at most 72 UTF-8 bytes). The response never contains passwordHash. Status input: `{ "isActive": false }` or true. Auth reloads role/status from the database on each request. Password changes do not revoke existing JWTs.

## Coupon API

Admins: GET/POST `/api/coupons`, GET/PUT/DELETE `/api/coupons/{id}`.
Authenticated customers: POST `/api/coupons/validate` with `{ "code": "SAVE10", "orderValue": 200000 }`.

Create/update fields: code, discountType (PERCENTAGE/FIXED_AMOUNT), discountValue, minOrderValue, startDate, endDate, usageLimit, isActive. Codes are uppercase; percentage is at most 100. Null dates/usageLimit mean unrestricted. Date endpoints are inclusive. DELETE deactivates the coupon and preserves history. Preview does not consume usage; checkout recalculates database prices and verifies eligibility under a row lock. Coupon updates and checkout refresh the entity under that lock to prevent stale usage counts.
